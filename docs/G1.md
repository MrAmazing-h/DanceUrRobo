# G1 full-body dance

This track transfers a pretrained GEAR-SONIC controller to a simulated G1 with Inspire DFQ hands. It does not train a new policy or control hardware.

## Reproduction

Follow the root README installation, asset-fetch and preparation commands. Python 3.11, MuJoCo 3.10.0 and ONNX Runtime CPU are the demonstrated runtime. Use a compute allocation on shared clusters. EGL requires a working graphics driver; dynamics alone does not require a GPU.

```bash
# After fetching assets and preparing the reference:
MUJOCO_GL=egl danceurrobo-g1 --workdir outputs/g1 --case native --duration 24
MUJOCO_GL=egl danceurrobo-review native --workdir outputs/g1
MUJOCO_GL=egl danceurrobo-g1 --workdir outputs/g1 --case half --duration 44 --rate 0.5
MUJOCO_GL=egl danceurrobo-review half --workdir outputs/g1
```

Case folders are under `outputs/g1/outputs/`. Choose a new case name to repeat a run. Review refuses to overwrite existing review products. A case whose name starts with `stand` uses the standing reference; other names use the dance after two seconds of standing. `--no-render` runs dynamics without video and therefore cannot be followed directly by the review command.

## Pinned public assets

- Unitree robot description: `unitreerobotics/unitree_ros@9926cc2f179ae3b86f4f74087bd32ef0c8b6fd90`, G1 29-DOF revision 1.0 with Inspire DFQ hands.
- SONIC source/template: `NVlabs/GR00T-WholeBodyControl@45c03facbf848e0c743091b7d9c17952096ff908`.
- SONIC controller: `nvidia/GEAR-SONIC@6733128a3d8a523b1418b06bca3cdf61c8b0987f` on Hugging Face.

The packaged asset manifest records every URL and SHA-256. The fetcher checks cached and newly downloaded files, refusing mismatched existing content. Model weights are downloaded separately, not committed. The trusted upstream human template is hash-verified before loading its pickle representation.

The derived XML includes a floating base, ground, gravity, joint actuation and hand mimic constraints. Mesh references are relative. It has 53 hinge joints, 60 qpos coordinates, 59 velocity coordinates, 41 actuators and 12 mimic equalities. The model is not a certified hardware twin. Its Inspire hands differ from the pretrained embodiment.

## Input and controller

The example is a derived 590-frame, 30 Hz SMPL-X sequence, not licensed body-model weights. Input NPZ fields include `fps`, `up_axis="Z"`, `units="meters"`, `global_orient[N,3]`, `body_pose[N,63]`, `global_joint_positions[N,55,3]` and `joint_names`. Rotation vectors are radians.

1. Spherical interpolation resamples rotations to 50 Hz. Canonical SONIC joint offsets and forward kinematics produce 24 selected points. Source betas are not used for the policy body shape. Finger rotations are zero.
2. Initial heading is aligned; source translation is not commanded as a base-position servo.
3. A 1,762-dimensional encoder input uses the official scalar mode encoding `[mode_id,0,0,0]`: mode 0 for G1 standing, mode 2 for SMPL motion. It is **not a one-hot vector**. The encoder produces 64 latent values.
4. The 994-dimensional decoder input combines that latent with robot observation history. The decoder commands 29 body joints, including legs, waist and arms. Hand targets stay neutral.
5. Joint PD torques are effort-clipped and applied to MuJoCo. No root overwrite, tether, gravity cancellation or episode reset keeps the robot upright.

The exact joint order, default posture, effort limits, armature-derived gains, doubled ankle/waist gains and action scales are in `controller.py`. Preparation writes resolved numerical arrays to `reports/adapter.json`. This publication does not retune the accepted experiment.

## Output contract

`trajectory.npz` contains actual simulated `time`, `source_time`, `qpos`, `qvel`, body positions and diagnostics, plus joint names and address mappings. Do not assume policy order and model hinge order are identical.

The bundled review exports `examples/g1/*_motion.npz` contain:

| Field | Meaning |
| --- | --- |
| time_s, source_time_s | Simulation and source time in seconds |
| qpos, qvel | MuJoCo state, 60 and 59 columns |
| joint_pos_rad, joint_vel_rad_s | All 53 hinge positions/velocities |
| joint_names, qpos_addresses, qvel_addresses | Explicit model mapping |
| root_pose_xyz_wxyz | World XYZ in meters; quaternion WXYZ |
| root_linear_velocity_world_m_s | World-frame translation velocity |
| root_angular_velocity_local_rad_s | MuJoCo free-joint local angular velocity |
| model, model_sha256 | Relative model reference and checksum |

World coordinates are right-handed Z-up; time is seconds and angles radians. These are **simulated state trajectories, not hardware command files**. The exported original-model checksum is retained separately when portable XML path references change.

Recorded states are 50 Hz and videos 25 Hz. Videos are renderings of the recorded dynamic rollout; the source skeleton is kinematic reference. The source last timestamp is 19.6333 s; the 50 Hz reference ends at 19.62 s (13.3 ms truncation). Full video lengths also include two seconds of initialization and a final hold. The GIF excludes initialization.

Recompute sampled contact and joint-limit diagnostics on a compute node:

```bash
danceurrobo-audit --model outputs/g1/models/g1_inspire_sonic.xml \
  --trajectory examples/g1/native_motion.npz --output outputs/native_audit.json
```

## Before any hardware work

Resolve hand collision geometry, effort/velocity constraints, state-estimation and joint mappings, motion-tracking quality, balance robustness and a safe start/stop procedure with the hardware team. The current repository provides **no hardware interface**. See the explicit failures in [results](RESULTS.md).
